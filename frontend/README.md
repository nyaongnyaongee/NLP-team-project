# 이음 프런트엔드 (React)

학교와 가정을 잇는 소통 앱 **이음**의 모바일 웹 프런트엔드입니다. 학부모는 교사에게 메시지를 보내고 공지를 읽고, 교사는 **원문이 아닌 정제문**을 보며 답장·대화 종료·할 일·일정·공지를 관리합니다. 서버는 `../backend`(FastAPI)입니다.

```
브라우저(이 프로젝트) ──/api──▶ Vite 개발 서버(5174) ──▶ FastAPI(8000) ── PostgreSQL
                  └─/api/ws (실시간 알림)
```

- 구현 명세와 단계별 완료 조건: `ieum-frontend-spec.md` (팀 문서)

## 주요 기능

| 역할 | 화면 | 하는 일 |
| --- | --- | --- |
| 공통 | 로그인 | 아이디·비밀번호 로그인, 역할별 시작 화면으로 이동, 새로고침해도 유지(탭을 닫으면 해제) |
| 학부모 | 대화 | 담임 교사에게 메시지 전송, 교사 답장 확인(실시간), 종료된 대화에도 다시 메시지를 보내면 대화가 재개 |
| 학부모 | 공지사항 | 게시된 공지 목록·상세 (게시되면 바로 나타남) |
| 교사 | 대화 목록 | 학생별 대화, 학부모 글의 **정제문** 확인, 답장, 대화 종료, 추출 결과(할 일·일정 후보) 확인 |
| 교사 | 할 일 / 캘린더 | 후보를 추가·수정·삭제, 할 일 체크, 월 달력과 날짜별 일정 |
| 교사 | 공지사항 | 공지 초안 작성·수정·삭제·게시(글자 수 제한 100/5000자) |
| 교사 | AI 초안 | 답장 초안, 공지 초안 (자동 전송·게시 없음, 보내기 전 확인 항목 표시) |
| 이관팀 | 준비 중 | 서버 기능이 정해지기 전까지 안내 화면만 |

핵심 규칙: 교사 화면은 정제 중·정제 실패 메시지의 원문을 **읽지 않습니다**(서버가 막는 것에 더해 프런트도 한 번 더 막음). 학부모 화면은 정제문과 정제 상태를 **표시하지 않습니다**.

## 기술 스택

React 19 · TypeScript · Vite 8 · react-router-dom 7 · oxlint
(상태관리·UI·CSS 라이브러리는 쓰지 않았습니다. 디자인은 데모의 CSS 두 파일을 그대로 사용합니다.)

## 어떤 전제로, 어떻게 구현했나

기준 문서는 두 가지입니다. **기획서**(`ieum-plan.md`: 무엇을 만들지, 완성 기준 F1-1~F4-8)와 **프런트엔드 구현 명세**(`ieum-frontend-spec.md`: 백엔드 코드를 분석해 정한 API 계약, 구조 규칙, 단계별 완료 조건). 두 문서는 저장소에 포함하지 않았습니다(아래 「포함되지 않은 파일」).

### 전제 (기획서와 명세에서 가져온 것)

| 전제 | 프런트에서 어떻게 반영했나 |
| --- | --- |
| **시연 가능한 수준**이 목표(기획서 4장). 실제 학교 연동·파일럿 운영은 범위 밖 | 시드 계정과 시드 대화로 끝까지 시연되게 만들고, 토큰 갱신·회원가입·푸시 알림 등은 만들지 않음 |
| **가장 중요한 목적은 학부모 폭언의 정제 후 전달**. 정제가 필요한 메시지의 원문은 교사 화면 어디에도 나오면 안 됨(기획서 3장) | 원문 차단은 서버가 보장하고, 프런트는 방어선을 한 번 더 둠. 교사 화면은 처리 중·실패 메시지의 `raw_text`를 **읽지 않음**, 학부모 화면은 정제 상태를 **표시하지 않음** (`features/chat/messageText.ts` 한 곳에서만 결정) |
| **서버가 최종 권한 판단**. 화면의 가드는 안내용 | 역할 가드는 이동만 처리하고, 403·404 등은 서버 응답을 그대로 안내 |
| **계약 우선**: 화면은 서버 API 계약을 기준으로, 데모는 디자인 기준으로만 사용(기획서 5장) | 서버 코드를 읽어 요청·응답 모양을 확인한 뒤 `src/api/types.ts` 한 파일에 옮김. 데모는 CSS와 마크업 구조만 사용하고 데모의 JavaScript는 가져오지 않음 |
| **뼈대 우선**: 가장 단순한 구조를 먼저 세우고 기능을 하나씩 얹음(기획서 5장) | 명세의 순서대로 S0(연결) → 로그인 → 메시지 한 줄 → 실시간 → 답장·종료 → 할 일·일정 → 공지 → AI 초안 → 디자인을 만들고, 단계마다 완료 조건을 직접 확인한 뒤 다음 단계로 감 |
| **최소 기술 선택**(명세 4.1) | React, TypeScript, Vite, React Router만 사용. 상태관리·UI·CSS 라이브러리와 목(MSW)은 쓰지 않았고, 백엔드가 있는 기능은 모두 실제 API로 구현 |
| **설정은 한 곳에서**(기획서 5장) | 서버 주소는 `vite.config.ts`의 `/api` 프록시 한 곳. 코드에서는 `/api`와 `/api/ws`만 사용 |
| **실시간은 알림만, 내용은 항상 GET**(명세 1.4) | 서버 알림에는 내용이 없으므로 받으면 해당 화면을 다시 조회. 끊기면 같은 조회 코드를 2초 폴링으로 재사용 |
| **정제·AI 호출은 비용이 듦**(명세 9장) | 기본은 꺼진 상태로 시험하고, 꺼진 상태의 실패 경로(정제 실패, 503)를 화면으로 확인할 수 있게 구현 |

### 서버가 아직 못 해 주는 것을 프런트에서 우회한 부분 (명세 2장·7장)

명세는 백엔드를 분석해 "고쳐야 하는 것"을 따로 정리했고, 프런트는 코드를 바꾸지 않고 아래처럼 우회했습니다. 근본 해결은 서버 쪽 수정이 필요합니다.

| 서버의 한계 | 프런트의 우회 |
| --- | --- |
| 학부모·교사가 **새 대화를 시작할 수 없음**(요청 B1·B2) | 시드 대화로 시연. 학부모 화면은 내 대화 목록의 첫 대화를 자동 선택 |
| 대화 응답에 **상대방 이름이 없음**(B1) | 대화 목록·제목을 학생 이름으로 표시 |
| 로그인 응답에 **사용자 id가 없음**(B4) | 메시지의 `sender_id`와 대화의 `teacher_id`를 비교해 내 글/상대 글을 판단(토큰을 해독하지 않음) |
| 학부모 응답에도 **`status`와 `report` 계열 필드가 내려옴**(B3) | 학부모 화면은 `status`를 읽지 않고, `report`·`reported_at`은 타입에 선언하지 않음(보안 해결이 아니라 사용 방지) |
| 할 일·일정 **직접 추가 API, 일정 장소 필드가 없음**(B5) | 대화에서 추출된 후보만 다룸. 직접 추가·장소는 만들지 않음 |
| 닫힌 대화에 **누가 보내든 대화가 다시 열림** | 종료된 대화에서는 교사의 입력창을 숨겨 실수로 재개되는 것을 막음 |
| `due_at`의 시간대 표기가 **확인되지 않았음**(B10) | 실제 응답과 서버 직렬화를 확인해 `+09:00` 오프셋이 붙는 것을 확정하고, 날짜 표시는 `formatDate.ts` 한 곳으로 |
| 신고·이관 API와 이관팀 권한 없음(B6) | 이관팀 화면은 로그인·역할 분기와 "준비 중" 안내까지만 |

### 기획서 완성 기준(F1~F4) 대비 구현 범위

| 기획서 항목 | 상태 |
| --- | --- |
| F1 로그인·역할별 화면(F1-1~F1-8) | 구현. 단, F1-4의 "토큰 만료 시 작성 중이던 메시지 보존"은 구현하지 않음(만료되면 로그인 화면으로만 이동) |
| F2 정제와 원문 차단(F2-1~F2-9) | 프런트 담당 부분 구현(전송 잠금, 정제 중·실패 표시, 다시 정제, 원문 차단 방어선, 학부모 화면의 정제 비노출). 가명처리(F2-8)·90초 제한(F2-10)·정제 자체는 서버 담당 |
| F3 대화·종료·할 일·일정 | 구현. 단 F3-2의 목록 항목은 **학생 이름과 상태만** 표시(상대방 이름·마지막 메시지·시간은 서버 응답에 없어 미구현), F3-9의 미완료 개수는 대화 목록이 아니라 **할 일 탭**에 표시, **F3-12(직접 추가)는 미구현** |
| F4 공지사항 | 구현. 단 F4-7의 **작성자 이름은 표시하지 않음**(서버에 없음) |
| 7장 화면 공통 규칙 | 로딩·빈 상태·오류 표시, 한국 시각 표시, 모바일 폭 기준 가운데 정렬, 텍스트로만 표시는 구현. "네트워크가 끊기면 **상단 안내**"는 미구현(오류가 난 화면 안에서 문구로 안내, 입력은 지우지 않음) |
| 하단 탭(7장) | 교사: 대화 목록·할 일·캘린더·공지사항(기획서와 동일). 학부모: **대화·공지사항**(기획서의 "메시지 작성"과 "대화 목록"을 한 화면으로 합침) |
| 10장 민원 신고·이관, PWA 설치 | 미구현 |

### 구현 방식의 핵심 규칙 (명세 4.4)

서버 호출은 `src/api/`에서만, 서버 응답 타입은 `types.ts` 한 곳, 메시지 표시는 `messageText.ts` 한 곳, 날짜는 `formatDate.ts`(`Asia/Seoul`) 한 곳, 서버나 사용자가 쓴 글은 JSX `{text}`로만 그림(`dangerouslySetInnerHTML` 금지), 원문을 `console.log`하거나 `localStorage`에 저장하지 않음, 토큰은 `sessionStorage`에만 저장. 확인 대화상자는 대화 종료·공지 게시·삭제에만 사용합니다(명세 8장에서 미리 정한 값).

## 폴더 구조

```
frontend/
  index.html, vite.config.ts      진입 HTML, 개발 서버(포트 5174)와 /api 프록시
  src/
    main.tsx, App.tsx             시작점, 라우트와 Provider
    api/                          서버 호출은 여기에서만 (client, 엔드포인트별 함수, types, ws)
    auth/                         로그인 상태(sessionStorage), 역할 가드
    realtime/                     실시간 알림 연결(허브)과 갱신 훅, 끊기면 2초 폴링
    components/                   공통 틀(AppShell, 하단 탭, 계정 줄, 아이콘)
    features/
      login, parent, teacher, team   역할별 화면
      chat      메시지 표시 규칙(messageText.ts), 입력창, 조회 훅
      tasks     할 일·일정(후보, 목록, 캘린더, 날짜 처리 formatDate.ts)
      notices   공지(교사 목록·편집, 학부모 목록·상세, AI 초안)
      drafts    AI 초안 공용(요청 상태, 확인 항목 상자)
    design/                       데모 CSS(수정 없이 복사), 앱 전용 보정 CSS, 로고
```

| 기획서 `ieum-plan.md`, 구현 명세 `ieum-frontend-spec.md`, 단계별 프롬프트, 데모 HTML | 팀 내부 문서·외부에서 저장한 파일이라 이 폴더에 넣지 않음(올릴 거라면 별도 `docs/` 권장) | 팀 공유 문서를 참고 |
| `src/design/teacher-profile.png` | 화면에서 쓰지 않는 2MB 파일이라 `.gitignore`로 제외 | 쓰게 되면 용량을 줄여 올림 |

> 이 폴더만 받아서는 **화면이 열려도 로그인할 수 없습니다.** 백엔드(8000번)와 DB가 켜져 있어야 로그인·메시지·공지가 동작합니다.

## 실행하기

### 1. 준비

- **Node.js 20.19 이상**(또는 22 이상) 설치 — https://nodejs.org (Vite 8 요구 버전)
- **백엔드 실행 환경**: PostgreSQL, Python, `.env` 설정은 저장소 루트 `README.md`의 「실행」 절을 따릅니다.

### 2. 켜기 (한 줄)

```powershell
cd backend
py dev\dev.py          # Mac: python3 dev/dev.py
```

DB·테이블·테스트 계정을 만들고 백엔드(8000), 확인 화면(5173), **React 화면(5174)** 을 함께 켠 뒤 브라우저로 **http://localhost:5174/** 를 엽니다. 끄기는 `Ctrl+C` (모두 같이 꺼짐).
`node_modules` 가 없거나 `package-lock.json` 이 바뀌었으면 `npm install` 도 알아서 합니다. (5173은 시험 화면입니다. 우리 앱이 아닙니다.)
**정제(Claude API 호출)는 기본이 꺼져 있습니다.** 켜려면 `py dev\dev.py --refine` (건당 약 0.006달러).

프런트만 따로 켜고 싶으면 (예: 백엔드는 이미 켜 둔 경우): `py dev\dev.py --no-react` 로 백엔드를 켜고, `frontend` 에서 `npm install` → `npm run dev`.

브라우저는 `/api`로만 요청하고 개발 서버가 8000으로 전달하므로(`vite.config.ts`) 서버의 CORS 설정은 건드릴 필요가 없습니다.

## 직접 테스트해 보기 (자동 테스트는 아직 없습니다)

화면 폭은 창을 좁히거나 개발자 도구(F12 → Ctrl+Shift+M)의 모바일 보기로 확인하세요. 넓은 화면에서는 가운데 430px 폭으로 보입니다.

1. **메시지와 원문 차단**: 학부모 탭에서 메시지 전송 → 내 화면에 바로 표시, 정제·상태 표시는 없음. 교사 탭 "민준"(또는 "지민")에 **새로고침 없이** "정제 실패 (정제가 꺼져 있습니다…)"(정제 끈 상태) 또는 정제문이 나타남. 교사 탭 개발자 도구 → Network에서 `messages` 응답의 `raw_text`가 `null`인지 확인.
2. **답장·종료·재개**: 교사가 답장 → 학부모 탭에 바로 표시. "대화 종료"(확인 후) → "종료된 대화", 입력창 숨김, 추출 상태 표시. 학부모가 다시 보내면 대화가 다시 열림.
3. **정제 다시 시도**: 정제 실패 메시지의 "다시 정제"를 누르면 "정제 중"으로 바뀌었다가 결과가 갱신됨.
4. **권한**: 학부모 탭 콘솔에서 종료 API를 직접 호출하면 403(`권한이 없습니다`).
5. **공지**: 교사 "공지사항"에서 초안 저장 → 학부모 화면에는 안 보임. "게시"(확인) → 학부모 "공지사항"에 바로 나타남. 게시한 공지도 수정·삭제 가능 — 수정하면 학부모 화면에 바뀐 글과 「수정됨」, 삭제하면 학부모 화면에서도 사라짐 (알림으로 바로 다시 읽음). 빈 제목·101자 제목·5001자 본문은 저장되지 않고 안내가 뜸.
6. **로그인 규칙**: 틀린 비밀번호, 빈 입력(요청이 나가지 않음), 로그인 없이 `/teacher` 접근, 로그아웃.
7. **실시간 복구**: 백엔드를 껐다 켜도 화면이 계속 갱신되는지(연결이 끊기면 2초 폴링, 복구되면 알림으로 전환).

### AI 기능(정제·초안·할 일 추출)을 시험하려면
이 기능들은 서버의 Claude 스위치가 켜져야 동작하고 호출마다 비용이 듭니다.

- 꺼진 상태(기본): 정제는 "정제 실패", 답장·공지 초안은 "Claude 가 꺼져 있습니다"(503), 후보 추출은 실패로 끝납니다. 오류 화면은 이 상태에서 확인할 수 있습니다.
- 켜려면: `backend/.env`에 `ANTHROPIC_API_KEY`를 넣고 `py dev\dev.py --refine`으로 실행(또는 5173 화면의 스위치). 학부모 메시지가 정제된 뒤에 답장 초안이 동작합니다.
- 할 일·일정 후보는 대화를 종료하면 서버가 뽑습니다. 꺼진 상태에서는 후보가 비어 있습니다.

### 깨끗하게 다시 시작하기
5173 시험 화면의 초기화(또는 서버의 `/dev/reset`)는 모든 대화의 메시지, 할 일·일정, 공지를 지우고 대화를 다시 엽니다(계정과 대화는 유지).

## 디자인과 폰트

- `src/design/sky-tokens.css`, `sky-app.css`는 데모에서 **수정 없이** 복사한 파일입니다. 고치지 말고, 앱만의 보정은 `app-layout.css`에 씁니다.
- 폰트 파일(Pretendard, 나눔스퀘어라운드)은 아직 없어 **시스템 폰트**로 동작합니다. 넣는 위치와 방법은 [src/design/fonts/README.md](src/design/fonts/README.md). 라이선스를 확인한 뒤 넣으세요. 빌드 때 "폰트를 찾지 못했다"는 경고가 나오는 것은 정상입니다.

## 개발 규칙 (요약)

- 서버 호출은 `src/api/` 안에서만, 서버 응답 타입은 `src/api/types.ts` 한 곳에만 둡니다.
- 메시지를 무엇으로 보여줄지는 `features/chat/messageText.ts` 한 곳에서만 정합니다.
- 날짜는 `features/tasks/formatDate.ts`를 거쳐 한국 시각(`Asia/Seoul`)으로 표시합니다.
- 서버나 사용자가 쓴 글은 JSX의 `{text}`로만 그립니다(`dangerouslySetInnerHTML` 금지). 원문을 `console.log`하거나 `localStorage`에 저장하지 않습니다.
- 토큰은 `sessionStorage`에만 둡니다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| 화면에 "서버에 연결할 수 없습니다" | 백엔드(`py dev\dev.py`)가 켜져 있는지, 8000번 포트를 확인 |
| 로그인이 안 된다 | 시드 계정은 `dev.py`가 만듭니다. 백엔드 터미널의 오류와 `.env`의 `DATABASE_URL`을 확인 |
| 5174 접속이 안 된다 | 터미널에 적힌 실제 주소를 확인(포트가 바뀌었을 수 있음). 5173은 백엔드 시험 화면 |
| `npm install` 또는 `npm run dev`가 실패 | Node 버전 확인(`node -v`, 20.19 이상), `node_modules`를 지우고 다시 `npm install` |
| 개발자 도구에 폰트 404 | 폰트 파일이 아직 없어서 나오는 정상 메시지(시스템 폰트로 표시) |
| 정제 실패만 나온다 | 정제 스위치가 꺼진 기본 상태입니다(위 「AI 기능」 참고) |
| 로그인 후 갑자기 로그인 화면으로 돌아간다 | 토큰 만료(12시간) 또는 서버 재시작 후의 무효 토큰. 다시 로그인 |
